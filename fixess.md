### Что нужно сделать

**1. Удалить вкладку "Новости" из нижней навигационной панели.**
Сейчас в нижнем меню есть вкладки: Главная / Заявки / Серви... / Парки... / Новос... / Проф...
Вкладку "Новости" нужно полностью убрать, ничем не заменять.

Просто подключить этот функционал к блоку на главном экране вместо нижней вкладки.

**3. Убрать "Объявления" и "Гости в ЖК" из вкладки "Сервисы".**
Эти два пункта сейчас продублированы внутри раздела "Сервисы" в нижней навигации. Их нужно оттуда удалить — они должны быть только в блоках главного меню.

- ❌ Убрать "Гости в ЖК" из вкладки "Сервисы"

## Фикс #2 — Сотрудники: читаемость временного пароля + отображение нескольких сотрудников одной специальности

### Скриншоты

**Скрин 1 — Модальное окно с временным паролем (плохая читаемость)**
![Временный пароль](fix2_screen1.png)

**Скрин 2 — Профиль сотрудника с его заявками**
![Профиль сотрудника](fix2_screen2.png)

**Скрин 3 — Список всех сотрудников**
![Список сотрудников](fix2_screen3.png)

### Что нужно сделать

**1. Исправить читаемость временного пароля в модальном окне.**
После добавления нового сотрудника появляется модальное окно с временным паролем (Скрин 1). Сейчас пароль отображается тёмным текстом на белом фоне — он плохо читается. Нужно сделать текст пароля контрастным и хорошо читаемым: например светлый фон + тёмный жирный текст, или тёмный фон + светлый жирный текст. Главное — пароль должен быть чётко виден.

**2. Исправить отображение нескольких сотрудников одной специальности в разделе "Сервисы".**
Сейчас когда в системе есть два и более сотрудника одной специальности (например, два Сантехника), при переходе в "Сервисы" → "Сантехник" отображается только один сотрудник. Нужно чтобы отображались все сотрудники данной специальности.

**3. Заявки каждого сотрудника должны отображаться отдельно и корректно.**
У каждого сотрудника в его профиле должны показываться только его собственные заявки (взятые в работу или выполненные). Заявки не должны перемешиваться между сотрудниками одной специальности — у каждого свой список.

### Итог
- ❌ Временный пароль плохо читается → сделать контрастным и хорошо различимым
- ❌ В разделе "Сервисы" при двух сантехниках показывается только один → показывать всех сотрудников специальности
- ❌ Заявки сотрудников перемешиваются → у каждого сотрудника строго свои заявки

## Фикс #3 — Восстановление пароля: код не приходит после выхода из аккаунта

### Скриншоты

**Скрин 1 — Экран ввода кода восстановления**
![Ввод кода](fix3_screen1.png)

**Скрин 2 — Экран входа (кнопка "Проблемы с авторизацией?")**
![Экран входа](fix3_screen2.png)

**Скрин 3 — Экран восстановления пароля (ввод email)**
![Восстановление пароля](fix3_screen3.png)

### Контекст проблемы

Бэкенд ранее предупреждал: для отправки кода восстановления через push-уведомление (FCM) у пользователя должен быть зарегистрирован FCM-токен в БД. Токен сохраняется при логине. Если пользователь вышел из аккаунта — токен может быть не актуален или отсутствовать, и код некуда отправить.

**Сценарий воспроизведения бага:**
1. Пользователь залогинен (житель или админ) — FCM-токен есть в БД
2. Пользователь выходит из аккаунта, чтобы попасть на экран входа
3. На экране входа нажимает "Проблемы с авторизацией?"
4. Вводит свой email и нажимает "Отправить код"
5. Push-уведомление с кодом **не приходит**

### Что нужно исправить

Предлагаю рассмотреть следующие варианты решения — выбери наиболее подходящий:

**Вариант А (рекомендуемый): отправлять код на email, а не через push.**
Восстановление пароля — стандартный сценарий именно для ситуации когда пользователь разлогинен. Push в этом случае ненадёжен. Отправлять 6-значный код на email пользователя — стандартная и надёжная практика. Поменять логику: при запросе восстановления отправлять код на указанный email, а не через FCM push.

**Вариант Б: сохранять FCM-токен при выходе из аккаунта.**
При логауте не удалять FCM-токен из БД (или хранить последний актуальный токен). Тогда при запросе восстановления токен всё ещё будет в БД и push дойдёт. Минус: если пользователь переустановил приложение — новый токен ещё не зарегистрирован.

**Вариант В: комбинированный.**
Попробовать отправить push по последнему известному FCM-токену, и одновременно продублировать код на email. Пользователь получит в любом случае.

### Итог
- ❌ После выхода из аккаунта код восстановления не приходит
- ✅ Нужно реализовать надёжную доставку кода — предпочтительно через email (Вариант А)
- ❌ Текущая зависимость от FCM-токена при восстановлении пароля — ненадёжна для разлогиненного пользователя
